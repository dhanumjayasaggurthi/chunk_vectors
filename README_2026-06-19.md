# EPOD Document Ingestion Pipeline — Operations Guide
**Last updated: 2026-06-19**

---

## What this pipeline does

Walks either a NAS/UNC share or an Amazon S3 bucket, finds PDF files, and:

1. Extracts text with PyMuPDF (layout-aware, 2-column reading order)
2. Runs Google Cloud Vision OCR on scanned pages and image regions
3. Extracts tables with pdfplumber (→ Markdown)
4. Chunks the content into 3 levels: TOC sections → page groups → sliding window
5. Optionally embeds chunks via Azure OpenAI `text-embedding-3-small`
6. Writes chunks + vectors to PostgreSQL + pgvector

Embeddings can be toggled off entirely; the rest of the pipeline still runs and stores text chunks with `NULL` vectors.

## Database — tables are created automatically

`init_db()` is called every time the pipeline starts.  
Every SQL statement uses `IF NOT EXISTS`, so the first run creates everything and subsequent runs are no-ops.

**What is created automatically:**

| Object | SQL | Notes |
|---|---|---|
| pgvector extension | `CREATE EXTENSION IF NOT EXISTS vector` | Needs superuser or `CREATE` privilege on the DB |
| Schema | `CREATE SCHEMA IF NOT EXISTS epod` | Configurable via `[POSTGRES] schema` |
| `ingestion_log_{folder}` | `CREATE TABLE IF NOT EXISTS …` | Per-document status tracking |
| `doc_chunks_{folder}` | `CREATE TABLE IF NOT EXISTS …` | Chunk text + vectors |
| HNSW vector index | `CREATE INDEX IF NOT EXISTS … USING hnsw` | Cosine distance, skips NULL vectors safely |
| 5 supporting B-tree indexes | `CREATE INDEX IF NOT EXISTS …` | On status, file_hash, doc_id, file_name, chunk_level |

**The only manual prerequisite** is that the PostgreSQL role used by the pipeline has permission to create extensions.  
Run this once as a superuser if needed:

```sql
GRANT CREATE ON DATABASE your_db TO your_pipeline_user;
-- or simply:
CREATE EXTENSION IF NOT EXISTS vector;   -- as superuser, then pipeline user can use it
```

When `enable_embeddings = false`, the `chunk_vector` column stores `NULL`.  
The HNSW index handles NULL rows correctly (they are not indexed and will not appear in similarity searches).

## config.ini — full template

```ini
[POSTGRES]
host     = your-postgres-host
port     = 5432
database = your_database
user     = your_user
password = your_password
schema   = epod
folder   = archive          # appended to table names: ingestion_log_archive, doc_chunks_archive

[PATHS]
# Choose "nas" (local/UNC path) or "s3" (Amazon S3)
source_type = s3

# Only used when source_type = nas
docs_root = /mnt/nas/EPOD/Archive

[S3]
bucket            = your-bucket-name
prefix            = EPOD/Archive/          # optional sub-folder; leave blank for root
region            = us-east-1
access_key_id     =                        # leave blank to use IAM role (recommended on EC2)
secret_access_key =
session_token     =                        # optional, for STS/assumed roles
temp_dir          = /data/tmp              # local download directory; MUST be on real disk, not tmpfs

[GCP]
gcp_key_path = /path/to/gcp-service-account.json

[AZURE_OPENAI_CHAT]
api_base    = https://your-instance.openai.azure.com
deployment  = gpt-4o
api_key     = your-key
api_version = 2024-02-01

[AZURE_OPENAI_EMBEDDING]
api_base    = https://your-instance.openai.azure.com
deployment  = text-embedding-3-small
api_key     = your-key
api_version = 2024-02-01

[PIPELINE]
enable_embeddings = true    # set to false to skip Azure embedding calls entirely
```

## Setup (Linux server)

### 1. Install Python dependencies

```bash
pip install -r requirements.txt
# requirements.txt includes: pymupdf pdfplumber pillow google-cloud-vision
#   psycopg2-binary pgvector openai boto3 markdown streamlit
```

### 2. Set file descriptor limit

PyMuPDF and pdfplumber each hold open file handles. With 16 parallel workers:

```bash
ulimit -n 65536

# To make it permanent, add to /etc/security/limits.conf:
# your_user  soft  nofile  65536
# your_user  hard  nofile  65536
```

### 3. Create config.ini

```bash
cp config.ini.template config.ini   # if template exists
# or create from scratch using the template above
chmod 600 config.ini                # protect credentials
```

### 4. Point temp_dir to real disk (S3 mode)

`/tmp` on most Linux servers is tmpfs (RAM-backed). Large PDFs will exhaust RAM if temp files land there.

```bash
mkdir -p /data/tmp
# then set temp_dir = /data/tmp in config.ini [S3]
```

### 5. Verify everything

```bash
# Check DB connectivity + auto-create tables
python db.py

# Dry run — lists what would be processed, no writes
python main.py --source s3 --dry-run --max-files 20

# Test with 10 real documents
python main.py --source s3 --no-embed --max-files 10 --doc-workers 2
```

## Running the pipeline

### Standard run (S3, no embeddings, 16 parallel workers)

```bash
python main.py \
  --source s3 \
  --no-embed \
  --doc-workers 16 \
  --workers 1
```

`--doc-workers 16 --workers 1` = 16 documents in parallel, 1 OCR thread per document.  
This keeps Vision API concurrency at exactly 16 (the safe limit).

### Standard run (NAS/local path, with embeddings)

```bash
python main.py \
  --source nas \
  --doc-workers 8 \
  --workers 2
```

### Preview what would run (no DB writes, no downloads)

```bash
python main.py --source s3 --dry-run
```

### Force re-ingest everything (ignores unchanged-file skip)

```bash
python main.py --source s3 --no-embed --force --doc-workers 16 --workers 1
```

### Process a single file

```bash
# S3 file
python main.py --file s3://your-bucket/EPOD/Archive/folder/document.pdf --no-embed

# Local file
python main.py --file /mnt/nas/EPOD/Archive/folder/document.pdf
```

### Retry only documents that previously failed

```bash
python main.py --source s3 --no-embed --retry-errors --doc-workers 8 --workers 1
```

### Check pipeline status

```bash
python main.py --stats
```

### Run in background (Linux, keep running after SSH disconnect)

```bash
nohup python main.py --source s3 --no-embed --doc-workers 16 --workers 1 \
  > logs/run_$(date +%Y%m%d).out 2>&1 &

echo $!  # note the PID for later

# Or with tmux:
tmux new-session -s epod
python main.py --source s3 --no-embed --doc-workers 16 --workers 1
# Ctrl-B D  to detach;  tmux attach -t epod  to re-attach
```

## CLI flag reference

| Flag | Default | Description |
|---|---|---|
| `--source {nas,s3}` | from config.ini | Override input source |
| `--no-embed` | false (embeddings ON) | Skip Azure embedding; store NULL vectors |
| `--doc-workers N` | 1 | Documents processed in parallel |
| `--workers N` | 4 (from config) | OCR page threads per document |
| `--dry-run` | false | Scan only, no DB writes, no S3 downloads |
| `--force` | false | Re-ingest even unchanged files |
| `--retry-errors` | false | Only process docs in ERROR state |
| `--file PATH` | — | Single file (local path or `s3://bucket/key`) |
| `--root PATH` | from config.ini | Override NAS docs_root |
| `--max-files N` | unlimited | Cap files (useful for testing) |
| `--stats` | — | Print DB status counts and exit |

**Safe concurrency formula:**  
`doc-workers × workers ≤ 16` (Vision API concurrent call limit)

Recommended combinations:

| Goal | Command |
|---|---|
| Most docs/day (text PDFs) | `--doc-workers 16 --workers 1` |
| Balanced (mixed scanned/text) | `--doc-workers 8 --workers 2` |
| Debug single document | `--doc-workers 1 --workers 4` |

## Resume behaviour

The pipeline is fully resumable. On any restart:

1. **S3 listing** — reads object metadata only (ETag + LastModified). ~3,000 API calls for 3M objects. Takes 3–5 minutes.
2. **DB lookup** — sub-millisecond B-tree index check per object.
3. **Fast-skip** — if `status = SUCCESS` and ETag matches: zero download, zero processing. Skipping 2M already-done docs takes ~10–15 minutes of DB lookups.
4. **Stale RUNNING reset** — on every startup, records stuck in `RUNNING` for more than 60 minutes are automatically reset to `PENDING` and reprocessed. This handles crash recovery without manual SQL.
5. **Error retry** — docs with `status = ERROR` and `retry_count < 3` are automatically retried on the next run.

**You can safely stop the pipeline at any time with Ctrl-C.** In-flight documents finish; the rest resume from where they left off on the next run.

## Throughput estimates (no embeddings, S3 source, Linux)

These are real-world estimates based on the pipeline architecture.  
Actual numbers depend on PDF size, OCR density, and network speed.

### Text PDFs (no OCR required)

Bottleneck: S3 download + pdfplumber table extraction

| Workers | Docs/day | 3M docs in |
|---|---|---|
| `--doc-workers 8` | ~70K | ~43 days |
| `--doc-workers 16` | ~130K | ~23 days |

### Scanned PDFs (Google Vision OCR required)

Bottleneck: Vision API (16 concurrent slot semaphore)

| Workers | Docs/day | 3M docs in |
|---|---|---|
| `--doc-workers 8 --workers 2` | ~25K | ~120 days |
| `--doc-workers 16 --workers 1` | ~46K | ~65 days |

### To run faster

- **Split the prefix** — run multiple pipeline instances pointing at different S3 prefixes (`EPOD/Archive/2020/`, `EPOD/Archive/2021/`, etc.), each with its own process and the same DB. The `RUNNING` status in the DB prevents double-processing.
- **Multiple EC2 instances** — all pointing at the same PostgreSQL DB and same S3 bucket. Works out of the box.
- **Enable embeddings later** — ingest all 3M docs with `--no-embed` first, then run a second pass with embeddings only on the already-chunked docs (requires a small script to iterate `doc_chunks` rows with NULL vectors).

## Database schema

Table names include the `folder` value from config.ini (e.g. `archive` → `ingestion_log_archive`).

### `epod.ingestion_log_{folder}`

| Column | Type | Description |
|---|---|---|
| `doc_id` | text PK | sha256 of normalised file path |
| `file_path` | text UNIQUE | Full path or `s3://bucket/key` |
| `file_name` | text | Filename only |
| `file_hash` | text | sha256 of file bytes (NAS) or S3 ETag (S3) |
| `file_size` | bigint | Bytes |
| `last_modified` | timestamptz | File mtime / S3 LastModified |
| `ingested_at` | timestamptz | First pipeline run |
| `updated_at` | timestamptz | Last status change |
| `status` | text | `PENDING` / `RUNNING` / `SUCCESS` / `ERROR` / `SKIPPED` |
| `error_message` | text | Last error (truncated to 2000 chars) |
| `retry_count` | int | Times attempted (permanently skipped at ≥ 3) |
| `chunk_count` | int | Chunks produced |
| `pages_total` | int | PDF page count |

### `epod.doc_chunks_{folder}`

| Column | Type | Description |
|---|---|---|
| `chunk_id` | text PK | sha256(doc_id + chunk_index) |
| `doc_id` | text FK | → ingestion_log |
| `file_name` | text | Source filename |
| `file_path` | text | Full path or `s3://bucket/key` |
| `chunk_index` | int | 0-based position in document |
| `chunk_total` | int | Total chunks in document |
| `chunk_level` | text | `section` / `page` / `split` |
| `section_title` | text | Nearest heading |
| `page_start` | int | First page (1-based) |
| `page_end` | int | Last page (1-based) |
| `content_types` | text[] | e.g. `{text,table,image}` |
| `chunk_text` | text | Extracted text |
| `chunk_vector` | vector(1536) | Embedding vector; `NULL` when embeddings are off |
| `created_at` | timestamptz | |
| `updated_at` | timestamptz | |

## Useful SQL queries

### Overall status

```sql
SELECT status, COUNT(*) AS docs, SUM(chunk_count) AS chunks, SUM(pages_total) AS pages
FROM epod.ingestion_log_archive
GROUP BY status
ORDER BY docs DESC;
```

### Documents still failing

```sql
SELECT file_name, retry_count, error_message
FROM epod.ingestion_log_archive
WHERE status = 'ERROR'
ORDER BY retry_count DESC, updated_at DESC
LIMIT 50;
```

### Reset a permanently-failed document

```sql
UPDATE epod.ingestion_log_archive
SET status = 'PENDING', retry_count = 0
WHERE file_name = 'problem_document.pdf';
```

### Reset all stale RUNNING records manually (if auto-reset wasn't enough)

```sql
UPDATE epod.ingestion_log_archive
SET status = 'PENDING', retry_count = 0
WHERE status = 'RUNNING';
```

### How many chunks have no vector (embeddings were off)

```sql
SELECT COUNT(*) AS chunks_without_vector
FROM epod.doc_chunks_archive
WHERE chunk_vector IS NULL;
```

### Similarity search (when embeddings are on)

```sql
SELECT
    file_name,
    section_title,
    page_start,
    chunk_level,
    chunk_text,
    1 - (chunk_vector <=> '[0.01, 0.02, ...]'::vector) AS similarity
FROM epod.doc_chunks_archive
WHERE chunk_vector IS NOT NULL
ORDER BY chunk_vector <=> '[0.01, 0.02, ...]'::vector
LIMIT 10;
```

## Troubleshooting

### Tables don't exist on first run

`init_db()` is called automatically every time `main.py` runs (except `--dry-run`).  
If it fails, the most common cause is the pgvector extension not installed:

```sql
-- Run as superuser:
CREATE EXTENSION IF NOT EXISTS vector;
```

Then restart the pipeline — it will create tables on its own.

### S3 access denied

```
botocore.exceptions.ClientError: An error occurred (403) when calling the HeadBucket operation
```

Check IAM permissions. Minimum required:
```json
{
  "Effect": "Allow",
  "Action": ["s3:ListBucket", "s3:GetObject"],
  "Resource": [
    "arn:aws:s3:::your-bucket",
    "arn:aws:s3:::your-bucket/*"
  ]
}
```

### Docs stuck in RUNNING after a crash

The pipeline auto-resets stale RUNNING records (older than 60 minutes) at startup.  
If you need to reset them immediately:

```bash
python main.py --stats          # shows how many are RUNNING
```
```sql
UPDATE epod.ingestion_log_archive
SET status = 'PENDING', retry_count = 0
WHERE status = 'RUNNING';
```

### Disk full during S3 run

Temp files land in `[S3] temp_dir`. With 16 workers and 5 MB average PDFs:
- Peak disk usage: 16 × 5 MB = **~80 MB** (normal)
- If disk is full, check that `temp_dir` points to real disk (not `/tmp` if it's tmpfs)

### Out of memory

The queue for 3M new docs holds ~3M `CrawlResult` objects in RAM (~1.5 GB).  
If the server has < 8 GB RAM, process in batches:

```bash
python main.py --source s3 --no-embed --doc-workers 16 --max-files 500000
# Run 6 times to cover 3M docs; already-done docs are fast-skipped each time
```
