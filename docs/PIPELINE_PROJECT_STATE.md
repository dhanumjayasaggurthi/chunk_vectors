## P0 — giant-document materialization and pinned publication (2026-11-27)

[4d3a029e](https://github.com/dhanumjayasaggurthi/chunk_vectors/commit/4d3a029e4d33deb2a5fb438f3a330e5998e65069) added server-side source batches, a bounded digest scan for current-document replay, and transactional chunk publication batches. The default source batch is 128 rows and the default write batch is 200 rows. These settings keep the semantic profile and chunk identity rules intact. A cold or changed document still constructs a document-scoped semantic graph. The native-only path releases page payloads during chunking and releases chunk objects as it prepares publication rows.

The [first giant PostgreSQL run](https://github.com/dhanumjayasaggurthi/chunk_vectors/actions/runs/46095041857/artifacts/15242439773) captured all 4,496 pages of the pinned USITC original in 308.747 seconds with zero native errors. It retained physical table bodies on 2,084 pages. Cold publication took 56.910 seconds and produced 16,245 chunks, including 4,659 physical-body chunks. Replay returned `SKIPPED` in 3.589 seconds with the same ordered 64,137,426-byte publication and SHA-256 `ad8a4671332b5f909105cfa39d59dfb859c0e6594c11d525cbc86909bc410e7f`. Both RSS gates failed because `getrusage()` carried the staging parent's RSS into the child measurements. A local memory-heavy parent reproduced the issue. The corrected harness measures each Linux executable image with `/proc/self/status` `VmHWM` and separately reports native staging peak RSS. The cold and replay limits remain 800,000 KiB and 200,000 KiB.

[70c854a](https://github.com/dhanumjayasaggurthi/chunk_vectors/commit/70c854ad88780cda71f20e42d48a426ea51c1682) also compares the native source hash, extraction version and publication timestamp inside the chunk transaction for caller-pinned input. A shared row lock holds that marker through commit. A disposable PostgreSQL regression changes the native extraction revision during chunk generation and verifies that the previous output and status survive rollback. The test also verifies that an independent reader sees the previous committed output after a replacement batch inserts. Locally, 10 materialization tests, 16 production tests, 17 semantic chunk tests and 3 open-grid tests passed. The production and materialization suites included disposable PostgreSQL.

The local paired A/B used the same Revision 2 spaced physical-body source rows, fixed document ID, retrieval profile and disposable output table. Fresh Python processes measured peak RSS with `VmHWM`. For baseline `f49bdc9` and candidate `70c854a`, cold publication took 85.388 and 87.478 seconds at 843,292 and 629,624 KiB peak RSS. Replay took 8.745 and 4.737 seconds at 812,452 and 88,732 KiB. All four runs produced the same ordered 16,245 chunks, including 4,659 physical-body chunks, with zero vectors. The shared 64,657,266-byte export had SHA-256 `718a0d5c94c2dde3a2f6e200625cf561a951d214a5b0555a0f2ed545656cc502`.

A layout review found conflicting version labels in the public original. The cover says Revision 1, while sampled tariff pages say Revision 2. The public regression pins the [official Revision 2 CSV](https://www.usitc.gov/2026_hts_revision_2) to SHA-256 `f6e95f2d39ef07c84fd3f5ffe987b1bab9b271d50638655eb6083d09355336ed`. The local strict-native run covered all 4,496 pages in 141.408 seconds on four workers. It verified 81,941 physical lines and 78 fields across 13 manually selected records on physical pages 912–914, 1050 and 2600. The chosen spans cover wrapped descriptions and special rates, suffix-only records, quantities and superscript footnotes. The audit compares each selected code, description, quantity and three duty columns. An injected adjacent-record rate swap failed the check. Production still publishes these as physical lines with the original footnotes and keeps logical tariff associations unverified.

At `4d3a029e`, [ingestion integration](https://github.com/dhanumjayasaggurthi/chunk_vectors/actions/runs/46095041808) and [rich-document validation](https://github.com/dhanumjayasaggurthi/chunk_vectors/actions/runs/46095041838) passed. The [CFR capture report and receipts](https://github.com/dhanumjayasaggurthi/chunk_vectors/actions/runs/46095041844/artifacts/15242704808) verify all eight public volumes and 6,353 pages. Independent verification covered all 6,353 pages in 272.112 seconds. Capture replay matched all eight source hashes and capture IDs in 272.074 seconds with zero re-renders.
